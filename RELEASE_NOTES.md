# Release notes

## 1.0.26
- Deploy hook: пауза 4с перед вызовом watchtower — ответ 202 успевает уйти
  до пересоздания контейнера (Actions видел 502).

## 1.0.25
- Тестовый бамп: проверка зелёного deploy hook (202 до пересоздания).

## 1.0.24
- Deploy hook отвечает 202 сразу: вызов watchtower ушёл в фоновый тред с
  ретраями — иначе watchtower убивал контейнер до ответа и Actions видел 502.

## 1.0.23
- Тестовый бамп: проверка deploy hook Actions → watchtower.

## 1.0.22
- Тестовый бамп для проверки deploy hook из GitHub Actions.

## 1.0.21
- Deploy hook в GitHub Actions: после сборки дёргает /deploy → watchtower
  обновляет контейнер сразу, не дожидаясь интервала.

## 1.0.20
- /mode в телеграме пишется в настройки юзера чата и перекрывает дефолт
  режима проекта — режим «вопрос» больше не игнорируется.

## 1.0.19
- Deploy hook: POST /deploy с Bearer-токеном пробрасывает обновление
  в HTTP API watchtower (порт наружу не публикуется).

## 1.0.18
- Команда /mode в телеграме: переключение режима код/вопрос и по аргументу
  (/mode ask|/mode code) и через инлайн-меню.

## 1.0.17
- В имени файла задачи теперь есть логин автора: `web-проект-юзер-дата-время`.
- Релиз-ноты: стартовое сообщение бота показывает «Что нового» по текущей версии.

## 1.0.16
- Юзер-боты маршрутизируются по secret_token (прокси режет путь /bot/<uid>).

## 1.0.14
- Per-user Telegram-боты: свой вебхук /bot/<uid>, ответы от своего бота,
  задачи идут под devin-ключом автора чата.

## 1.0.13
- Имя файла задачи сокращено: `web-проект-дата-время`.

## 1.0.10
- Задача идёт под devin-ключом и git-идентичностью того, кто её поставил
  (таблица tasks.user), а не владельца проекта.

## 1.0.9
- Фолбэк: если devin.api_key юзера отклонён (Invalid token), задача
  перезапускается с дефолтным ключом + предупреждение в выводе.

## 1.0.8

- Выбор проекта в вебе теперь per-user (project_web:<uid>).

## 1.0.7

## 1.0.6
