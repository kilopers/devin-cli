## 1.8.65 — настоящая причина роста страницы: процентный flex-basis

- Ряд ленты имел `flex:1` → `flex-basis:0%`. Процентный basis при
  indefinite-высоте родителя (`min-height:100vh`, не `height`) по
  спецификации резолвится в `auto` = высоте контента: после подгрузки
  карточек/панелей ряд разворачивался по контенту, страница росла,
  колонки тянулись до низа. minHeight:0 не помогал — ломался basis,
  а не min-height.
- Заменено на `flexGrow:1 + flexBasis:0` (абсолютный px, резолвить
  нечего): ряд всегда ровно в оставшееся место экрана. Проверено
  headless-браузером: document.scrollHeight == innerHeight и на
  десктопе, и на мобильном; внутренний скролл колонок сохранён.

## 1.8.23 — перенос карточек по канбану (dnd + уровни)

- Карточки перетаскиваются между колонками и по месту внутри них:
  ручка-гриппер в шапке карточки (десктоп), пунктирный
  плейсхолдер показывает точку вставки. На мобильной — иконка
  «переместить» с диалогом выбора темы (у каждой подписан уровень и
  «запустится»/«просто перенос»).
- Уровни карточек: заметка < спросить < код; уровень колонки = её
  эффективный режим. Повышение уровня = запуск: заметка → ask/code
  уходит в queued с дефолтами целевой темы, done-вопрос → code —
  переход «▶ в работу». Равный/понижение — просто перестановка,
  идущие задачи тоже только едут.
- «▶ в работу» у ask-карточки — селект code-тем: выбранная колонка
  забирает карточку и запускает её (/api/task/move).
- У заметки убрана кнопка «▶ начать выполнение» — в работу она
  уходит только переносом в колонку уровня «спросить»/«код».
- Бэк: POST /api/task/move {stem, topic, above?, below?} — смена
  темы + позиции (tasks.sort, среднее между соседями) и уровневые
  переходы; /api/tasks отдаёт sort и сортирует выдачу по нему.
  Миграция: tasks.sort DOUBLE (стартовый = created).

## 1.8.22 — «▶ в работу» той же карточкой

- Кнопка «▶ в работу» в модалке ask-задачи больше не создаёт новую
